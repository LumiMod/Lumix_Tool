# DC-S5 (MC801) V2.9 固件深度核验与隐藏功能盘点（2026-11-25）

> 本文档汇总基于本地 `S5___V29.bin`、`S5D__V29.bin`、`program.bin`、`postboot3.bin`、`rootfs1` 的静态反汇编核验，以及 DC-S5 V2.9 实机 Service USB（`04DA:2370`）RAM 实测结果。

---

## 1. 全部 28 项相机音效映射（反汇编实证）

- **AES-5 解密核验 `music` 分区**：使用 5 轮 AES-128-CBC 解密 `music`（3,538,944 字节，SHA-256 校验通过），确认为 8-bit 原始 PCM 背景音乐流，不含 28 项提示音元数据。
- **全部 28 项提示音逻辑均在 `program.bin`**：反汇编 `AUDIO_PlaySound`（`0x86479B38`）、`AUDIO_PlaySoundLoopStart`（`0x86479B96`）、`AUDIO_PlaySoundIntermittently`（`0x86479C56`）、`PlayBeep`（`0x8667583E` / `0x86675896`）及音调映射函数（`0x86473FDE` / `0x86473FF2` / `0x86474006` / `0x8647401A` / `0x86721CE8`），结合原厂 28 段 PCM 波形特征确认完整映射：

| 编号 | 时长 / 特征 | 对应机身动作 | 代码实证依据 |
|---|---|---|---|
| **#0** | 273 ms · 1.8 kHz | **自拍倒计时滴答音** | `0x8644FCE0` 倒计时循环：前段 0.5 s、最后 2 s 加速为 0.25 s 调用 `id=0` |
| **#1 / #2 / #3** | 164 ms · 双声 | **AF 合焦 / 提示音（音调 1 / 2 / 3）** | `0x86473FDE` 按电子音音调（0/1/2）映射 `1/2/3`；`#1` 另被 6 处通用确认硬编码调用 |
| **#4** | 467 ms · 4 脉冲 | **操作 / 警告提示音** | 位于 `PlayBeep` 静音拦截白名单 `{1,2,3,4,8,10,20,21,22}` |
| **#5** | 1078 ms · 5 脉冲 | **拍摄状态长提示音** | `0x867ACC94` 默认 `id=5`（特定条件切 `id=1`）调 `PlayBeep` |

| **#17 / #18 / #19** | 218 / 273 / 273 ms | **电子快门·慢门后帘闭合音（音调 1 / 2 / 3）** | `0x867AE39A`（慢门结束回调）与 `0x8647401A`（`r1==0`）映射 `17/18/19` |

## 2. S5 vs S5D V2.9 固件比对 & 1080p 180/150fps

- **全分区比对**：`S5___V29.bin` 与 `S5D__V29.bin` 的全部 **48 个分区 SHA-256 及容器头部完全一致（0 处差异）**。
- **1080p 180fps / 150fps**：原厂 S5 的 VFR / S&Q 帧率表（`0x86F15C2C`–`0x86F15CD2`）已开放 `1, 2, 5, 10, 15, 30, 60, 100, 120, 150, 180 fps`，模式拨盘切至 **S&Q** + FHD 即可直接使用（无音频、自动切 MF）。常规有声/AF 录制表最高为 60p/50p，无隐藏的常规 1080p 150/180fps 规格。

## 3. 视频端隐藏规格盘点（`program.bin` 画质源表，共 417 条）

### 3.1 具有实机解锁潜力的隐藏规格
1. **扩展 6K / 5.9K / 5.4K 帧率（HEVC 10-bit 200 Mbps）**：
   - NTSC 白名单（`0x86F15E88` / `0x86F15E8C`）与 PAL 白名单（`0x86F15ED6` / `0x86F15EDA`）、PAL 活动模板（`0x08A68C84`）均已核实。
   - 可扩展：`5.9K 16:9 29.97p`（`0x00F4`）、`5.9K 16:9 25p`（`0x00F3`）、`5.4K OG 3:2 25p`（`0x00EF`）、`C4K 23.98p 150M 4:2:2 10-bit`（`0x00B7`），以及画质表内的 `6K OG 24.00p`、`5.4K OG 29.97p`。
2. **6K / 5.9K / 5.4K 目标码率提升（200 Mbps → 300 Mbps）**：
   - 核实 `program.bin` 偏移 `0x788A7C`、`0x788AF0`（6K OG `5952×3968`）、`0x788B64`、`0x788BD8`（5.4K OG `5376×3584`）、`0x788C4C`、`0x788CC0`、`0x788D34`、`0x788DA8`（5.9K `5888×3312`）均存放 `200,000,000`（`0x0BEBC200`）。
   - **注意**：每组条目连续有两个 `200,000,000` 字段（`+0x00` 与 `+0x04`），实机需验证是否需要同时修改。
3. **S1H 同款高阶规格（待实机验证传感器读出链路与散热/卡速）**：
   - **5K 4:3 变形宽银幕** `4992×3744`（29.97p / 25p / 23.98p / 24p，200M HEVC 10-bit）
   - **400 Mbps ALL-Intra**：`C4K 4096×2160`、`4K 3840×2160`、`4K-A 3328×2496`（29.97p / 25p / 23.98p / 24p），以及 `FHD 200M ALL-I`、`2K DCI 2048×1080 220M`
   - **C4K 59.94p / 50p 200M HEVC 10-bit**、`4K-A 59.94p / 50p 200M`

### 3.2 同平台硬件不支持的残留（避坑）
- `7680×4320`（8K）、`6496×4320`、`5760×4320` 属于同平台 S1R（47MP）遗留，S5 传感器物理像素仅 `6000×4000`，无法拍 8K。

## 4. 拍照端隐藏功能与机内 LUT 直出实机验证

### 4.1 机内 JPEG 直出 LUT（已进入实机探针阶段）
- **静态 + 实机 RAM 核验全部通过**：
  - `postboot3`（加载基址 `0x87707000`）中 `0x877537A2` 确为 `bl 0x87864acc`，所属函数 `0x87753790` 符号为 `StcWrapperVclJpegRec::setStartParam(...)`（硬件 JPEG 编码器启动前填写 YUV 内存描述符的入口）。
  - `0x879F7900` 尾部有 5.17 MB 全 `0xFF` 空白区，实机 RAM 中可读可写，且在 `0x877537A2` 的单条 Thumb-2 `BL` 跳转范围内。
  - 实机读取 `0x08A9D47C` 确认存在 5 个机内 LUT 槽位指针（`0x062B6000` 起，每槽 `0xC00` 字节），槽位 0 开头确为 `0xBEEF`；ViewAssist 全局结构基址 `0x08BDC2C0`，`0x08BDC310`/`0x08BDC314`/`0x08BDC330` 对应监看开关与 `lut_id`。
- **实机待测风险点**：2400 万像素（`6000×4000`）纯 CPU 运算耗时与看门狗超时、以及硬件 DMA 编码器的 D-Cache 一致性问题（已部署 116 字节只读探针待拍照回读 `0x8F300000` 日志）。

### 4.2 手持高像素模式（待进一步验证）
- `program.bin`（`0x865BC0BC`–`0x865BC394`）高像素 IPU 输入结构体中存在 `HandHeldModeSW`、`LightweightModeSW`、`hheld_BayerArray`、`hheld_NumOfFrame` 及 16 帧输入指针（`InAdr_img1..img16`），而 S5 菜单仅开放了三脚架 8 帧高像素。后续可检查 `ipu_code` 协处理器是否实际实现了手持配准算法。

### 4.3 已确认固件未内置 / 原厂已开放项
- **未内置**：`L.ClassicNeo`、`Leica Monochrome`、10-bit HEIF 照片编码器、30fps RAW SH 连拍。
- **原厂已开放**：65:24 XPan、2:1、Live View Composite（实时复合）、对焦包围、HLG `.HSP`、14-bit RAW、6K 照片。
